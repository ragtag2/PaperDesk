# Domain docs

## Before exploring

This repo uses a single-context layout:

- Read the root `GLOSSARY.md` for domain terms.
- Read decisions in `docs/adr/` relevant to the area being explored.

If these files do not exist, proceed silently. Create them through the domain-modeling skill when terms or decisions are resolved.

## Vocabulary and decisions

Use glossary terms consistently in issues, proposals, hypotheses, and tests. Reconsider unfamiliar terminology; note real vocabulary gaps for domain modeling.

If a proposal contradicts an ADR, identify the ADR and explain why its decision should be reconsidered.
